## App changes

- `neon.ts`, `.neon`, root Neon dependencies and lockfile were generated by the CLI.
- `npm run build` validates all backend/simulator JavaScript and compiles the admin.
- `npm run start:neon` explicitly injects Neon's env settings into the existing stack.
- `npm run neon:init-db` uses the direct URL and refuses to replace existing tables.
- `npm run test:neon` performs live HTTP/database/realtime integration checks.
- Hosted PostgreSQL uses the existing `pg` driver, a five-connection pool, verified
  TLS and Sri Lanka timezone; transactions retain one client until commit/rollback.
- Hosted mode disables local SQL snapshot exports. Local PGlite support is retained.
- Call progress now checks predecessor states atomically when updating PostgreSQL,
  preventing delayed webhook updates from moving the call backwards. It records an
  answer when an advanced connection state arrives before the connected event.
- Automatic desktop call-window opening can be disabled for automated checks.

## Issues encountered and resolution

1. Restricted shell DNS prevented the official skill fetch. The first elevated
   approval review timed out; the permitted retry succeeded.
2. CLI authentication was initially missing; the browser login subsequently worked.
3. Automatic approval review initially blocked export of the saved records. The
   import ran only after the user explicitly approved that exact data transfer.
4. The first live call test exposed out-of-order status updates with remote latency.
   The atomic transition fix and both the regression and live retest passed.
5. PGlite's default Windows temp directory aborted in the restricted environment.
   Isolated tests passed using a workspace-local temporary directory.

Remaining: publish the reviewed source, deploy API/admin on Render, configure
their HTTPS URLs, and verify Android over mobile data without USB. Free sleeping
servers cannot provide reliable unattended check-ins; manual demo calls are the
verified scope.
