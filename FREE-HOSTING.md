# Free hosting for the academic demonstration

This setup uses Render Free for the Express API and its private call simulator,
Render Static Sites for the admin website, and Neon Free for persistent PostgreSQL.
The installed Android app connects directly to the hosted API over HTTPS. No USB
connection or running PC is needed after a successful deployment and phone test.

The Neon database is now linked, imported with user approval, and tested against
the real app. Its project is `hidden-sunset-83803730`, branch `production`.
See `NEON-SETUP-RESULT.md` for verified results. Publishing the changed source,
deploying the backend/admin to Render, and testing the public URLs remain before
the whole application is hosted.

## 1. Accounts and plans

- Sign in at <https://dashboard.render.com/> using the GitHub account that can
  access the project repository. Use the Hobby workspace and Free instance.
- Create a project named `suva-voice-demo` at <https://console.neon.tech/> on Free.
  Select Singapore if available, otherwise a nearby region.
- Use the included provider URLs. A purchased domain is unnecessary.

## 2. Initialize a new hosted database without touching local records

For this checkout this step is **already complete**. Do not repeat it. `neon deploy`
pulled the PostgreSQL variables into the ignored root `.env.local`; the initializer
and `npm run start:neon` use them. Private demo sign-in details are stored only in
`.runtime/Hosted-Demo-Access.txt`.

The instructions below are for a future new, empty database.

Create `.runtime/hosting.env` in this project folder. The `.runtime` directory is
ignored by Git. Put these two settings in that private file:

```dotenv
DATABASE_URL=postgresql://YOUR_NEON_CONNECTION_STRING
HOSTED_DEMO_PASSWORD=YOUR_PRIVATE_TEAM_DEMO_PASSWORD
```

Copy the Node.js PostgreSQL URL from Neon's **Connect** dialog; keep its TLS
parameters. Prefer `sslmode=verify-full` to verify the server certificate. Use
the direct/unpooled URL for this one-time import. The password must contain at
least 12 characters. Do not paste connection strings or passwords into chat.

From the project root, run:

```powershell
node Backend/scripts/init-hosted.js
```

This imports `Database/schema.sql` and the saved `Database/suva_voice.sql` snapshot
into a **new, empty hosted database**, then applies the free-plan migration.
It refuses any database already containing public tables. Import and password
changes run in one transaction. The local PGlite database is not opened.

All imported demo accounts retain their emails and receive the private team
password from this file. This prevents the publicly documented repository demo
passwords from working on the internet. Use fictional project records only.
This shared password is for the team's academic demo; real users should set
individual passwords before any real use.

Never use `npm run setup` or `npm test` against a database whose records you want
to preserve: the original setup/acceptance scripts reset their data.

## 3. Publish the updated source and create Render services

The local downloaded folder is not a Git checkout. The changed hosting files must
reach the GitHub repository before Render can build them. Keep the contents of
`Suva-Voice-main` at the repository root, with `render.yaml` beside `Backend`,
`Web`, `LocalServer`, `Audio`, and `Database`.

Publish source files only. Exclude `.runtime`, all `.env` files, database data
directories, `node_modules`, APKs, native build caches, and generated build output.
Do not replace the saved database snapshot with unrelated seed data.

In Render, create a Blueprint from the repository using `render.yaml`. It declares
one **Free** Node web service and one static site; no paid database/disk is declared.
You will be prompted for:

| Service | Variable | Value |
| --- | --- | --- |
| API | `DATABASE_URL` | The initialized Neon database URL, with TLS enabled |
| API | `WEB_URL` | Exact HTTPS URL assigned to the admin static site |
| API | `APP_URL` | Same admin URL for this Android-only deployment |
| Admin | `VITE_API_URL` | Exact HTTPS URL assigned to the API |

The API's `JWT_SECRET` and `VOICE_WEBHOOK_SECRET` are generated by Render.
If assigned site names differ from the requested names, update the variables to
match the actual URLs. `APP_URL` is a browser CORS setting; the Android app has no
browser origin. Redeploy the admin after setting `VITE_API_URL`, because Vite
embeds it during the build.

If the Blueprint wizard requires URLs before creating resources, use temporary
values, create both services, then correct these three URLs and redeploy both
before testing. Prefer manual service creation below if easier.

### Equivalent manual settings

API web service (repository root, **Free**, Node 22):

```text
Build: npm ci --prefix Backend && npm ci --prefix LocalServer
Start: node scripts/start-hosted.mjs
Health check: /api/health
```

Add `DATABASE_URL`, `JWT_SECRET`, `VOICE_WEBHOOK_SECRET`, `WEB_URL`, `APP_URL`,
`NODE_ENV=production`, and `NODE_VERSION=22` to the API environment. Use two
different random secrets of at least 32 characters. Never put the database URL
or these secrets in frontend/mobile variables.

Admin static site (repository root):

```text
Build: npm ci --prefix Web --include=dev && npm run build --prefix Web
Publish directory: Web/dist
VITE_API_URL: exact API HTTPS URL
Rewrite: /* to /index.html
```

## 4. Connect the installed Android app

After the API health URL returns `ok: true`, open the phone app's sign-in screen,
find the **Suva Voice server** field, and replace `http://127.0.0.1:4000` with the
API's HTTPS base URL (without `/api` or a trailing slash). Save and sign in with
an existing customer email and your private hosted demo password. Sign out of an
old local session first if needed. No APK rebuild is needed for that setting.

An optional future APK can embed this URL using `EXPO_PUBLIC_API_URL`; the
existing USB build and launcher remain the local fallback.

## 5. Checks before presenting

1. Open the hosted `/api/health` URL and allow the service to wake up.
2. Sign in to the hosted admin with the imported admin email and private password.
3. Sign in on Android using mobile data, with USB disconnected, to confirm the
   phone actually uses the hosted API.
4. Create a harmless demonstration record. Restart the API and verify it remains.
5. Start a manual call, play the browser/app prompt, press 1/2/3, and verify call
   history plus the matching alert. Check one customer cannot view another's data.
6. Verify sign-in and page refresh on a nested admin route.

The hosted launcher disables Windows desktop audio, Asterisk, automatic scheduling,
real email/SMS and real payments. It keeps manual call simulation, API-served
audio and Socket.IO available. The simulator runs on a private loopback port
alongside the API, so it does not require a second free web-service allocation.

## Free-plan limits

- Render Free web services sleep after 15 minutes without incoming traffic; waking
  can take about a minute. Scheduled calls and retries cannot be relied upon while
  asleep. Open the service shortly before the demonstration.
- Render's filesystem is temporary. Hosted records live in Neon; local automatic
  SQL-file snapshots are disabled only when `DATABASE_URL` is supplied.
- Neon Free currently includes 1 GB/project and 100 CU-hours/project/month and
  scales compute to zero when idle. Monitor the account's current usage limits.
- No real telephone calls, SMS charges or payment gateway are included.
- Stay on the free plans. Provider quotas can suspend service when exhausted;
  Render can bill excess bandwidth/build usage if a payment method is attached.
  Leave it unattached for this free demo unless Render explicitly requires it,
  and check any billing prompt before continuing.
